# Lua API: chams

Чамсы накладываются при генерации примитивов модели. Скрипт может управлять цветом и материалом для семи целей: `enemy`, `enemy_invisible`, `team`, `team_invisible`, `local`, `arms`, `weapon`. Первые четыре канала относятся к моделям игроков: видимые и проходящие сквозь стены слои независимы. `local` относится к модели самого игрока, которая обычно видна только в третьем лице; `arms` и `weapon` относятся к HUD-моделям рук и оружия от первого лица. Эти три канала не проходят сквозь стены.

## Штатные настройки через `settings`

Категории: `chams enemy`, `chams enemy invisible`, `chams team`, `chams team invisible`, `chams local`, `chams arms`, `chams weapon`. В каждой есть `chams` (boolean), `primary color` (RGBA `{r,g,b,a}`) и `primary material` (integer). Материалы: `0` = bloom, `1` = glow, `2` = flat. Например:

```lua
settings.override("chams arms", "chams", true)
settings.override("chams arms", "primary material", 2)
settings.override("chams arms", "primary color", {255, 180, 120, 220})
```

Для возврата значения пользователя вызови `settings.override(category, field, nil)` для каждого переопределённого поля. Эти поля сохраняются в конфиге; параметры элементов `ui.create` сохраняются вместе с Lua-профилем. Если скрипт создаёт собственный материал через `chams.create_material`, его параметры задаются кодом скрипта и сам объект материала не сериализуется в конфиг.

## Материал, создаваемый скриптом

`chams.create_material(brightness, tint) -> handle` создаёт вариант `solidcolor.vfx` с заданной яркостью `0.1..8` и RGB-оттенком `{r,g,b,a}` (альфа в материале игнорируется). Функция вызывается один раз в верхней части Lua-файла при загрузке; вызов из `paint` или другого callback запрещён. Создаются видимый и `ignorez` варианты. Возвращённый целочисленный handle принадлежит только этому скрипту. Не передавай его другому Lua-файлу; после перезагрузки создавай заново. Ограничение: 8 материалов на скрипт и 32 попытки создания за сессию DLL. Ресурсы движка живут до завершения сессии, поэтому частая перезагрузка скрипта может исчерпать лимит.

`chams.set(target, handle, color)` выбирает созданный материал для одной цели и задаёт цвет RGBA. `target` — одно из имён `chams.targets()`. `chams.set(target, nil)` снимает назначение. Вызов возможен из Lua callback, поэтому цвет можно анимировать в `paint`. Последний вызов между скриптами для одной цели выигрывает; при выключении или ошибке скрипта его назначения перестают применяться. Если Lua не назначила материал для цели, используется штатная настройка. Таким образом, собственный материал не требует менять глобальные поля конфига.

```lua
local mat = chams.create_material(1.2, {200, 230, 255, 255})
local enabled = ui.create("checkbox", "my_arms", "My arms", false)
events.on("paint", function()
    chams.set("arms", ui.get(enabled) and mat or nil, {80, 170, 255, 230})
end)
events.on("shutdown", function() chams.set("arms", nil) end)
```

Примеры: [custom_flat_chams.lua](examples/custom_flat_chams.lua) для противников, [hands_weapon_chams.lua](examples/hands_weapon_chams.lua) для рук и оружия, [local_player_chams.lua](examples/local_player_chams.lua) для локального игрока.

### Ограничения и проверка в игре

Lua не принимает произвольный KV3/VMAT-текст, путь к shader или указатель на материал. Это намеренное ограничение нативного парсера: скрипт задаёт только числовые параметры фиксированного `solidcolor.vfx`. Материалы bloom/glow/flat и готовые Lua-варианты можно свободно переключать по поддерживаемым целям, но API не даёт создавать произвольные шейдеры или менять все внутренние параметры движка. Не называйте эту часть «полным доступом к любому материалу».

Без сборки DLL нельзя проверить загрузку материала движком и классификацию HUD-моделей. После сборки проверь отдельно: противника, союзника, локального игрока в третьем лице, руки и оружие в первом лице, затем смену карты и выключение Lua. Если материал не создался, Lua выдаст `engine could not create the cham material`. Штатные bloom/glow при этом остаются доступными.
